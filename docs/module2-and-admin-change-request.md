# ТЗ на доработки: module2 и astrakhan-admin

## Цель

Зафиксировать функциональные изменения для двух частей системы:
- `module2` (клиентский модуль, корзина/оформление заказа).
- `astrakhan-admin` (модуль сотрудников, работа с точками на карте и предложениями точек).

---

## 1) Доработка `module2`: поведение формы доставки в корзине

### 1.1. Бизнес-требование

Если пользователь выбирает тип доставки **«Самовывоз»**, поле ввода адреса клиента должно быть скрыто.  
Вместо него необходимо показать адрес(а) пункта выдачи, откуда пользователь может забрать заказ.

### 1.2. Функциональные требования

1. В форме оформления заказа при выборе способа доставки:
   - **Курьером**:
     - показывается поле «Адрес клиента» (как сейчас).
   - **Самовывоз**:
     - поле «Адрес клиента» скрывается и не является обязательным;
     - отображается блок «Адрес самовывоза» (или список адресов, если их несколько).

2. Для самовывоза должна передаваться информация о выбранном пункте:
   - `pickupPointId` (обязателен для самовывоза),
   - `pickupAddress` (может храниться как отображаемое значение/снапшот).

3. Валидация перед отправкой заказа:
   - для **курьера** обязателен `customerAddress`;
   - для **самовывоза** обязателен `pickupPointId`, а `customerAddress` должен игнорироваться.

4. Отображение в подтверждении заказа:
   - для самовывоза: «Способ доставки: Самовывоз» + адрес точки выдачи;
   - для курьера: «Способ доставки: Курьер» + адрес клиента.

### 1.3. UI/UX требования

- Блок самовывоза визуально оформляется в стиле формы заказа (единые отступы, типографика, поля).
- При переключении типа доставки форма должна обновляться без перезагрузки страницы.
- Текст-подсказка для самовывоза: «Забрать заказ можно по адресу: ...».

### 1.4. Критерии приёмки

- При выборе самовывоза поле адреса клиента не видно и не валидируется.
- При выборе курьера поле адреса клиента видно и обязательно.
- Заказ с самовывозом нельзя отправить без выбранного пункта выдачи.
- В заказе корректно сохраняется и отображается тип доставки и соответствующий адрес.

## 2) Доработка `astrakhan-admin`: работа с точками на карте

### 2.1. Бизнес-требование

Упростить работу сотрудников с координатами:
- вместо ручного ввода широты/долготы — выбор точки на карте;
- при одобрении «предложенной точки» должна быть возможность сразу перейти в форму создания точки с предзаполненными данными.

### 2.2. Функциональные требования (создание/редактирование POI)

1. В форме добавления/редактирования POI реализовать компонент выбора координат на карте:
   - клик по карте устанавливает маркер;
   - координаты `latitude/longitude` автоматически подставляются в форму;
   - при наличии координат в форме маркер отображается в соответствующей позиции.

2. Сохранить возможность ручной корректировки координат как fallback (опционально, но желательно).

3. Добавить действия:
   - «Выбрать на карте» (активирует режим выбора),
   - «Очистить координаты» (снимает маркер и очищает поля).

### 2.3. Функциональные требования (предложения точек)

1. В списке предложений точек (pending/moderation) для статуса «Одобрено» добавить сценарий:
   - кнопка/действие **«Создать POI из предложения»**.

2. При переходе в форму создания POI из предложения:
   - предзаполнить данные (название, описание, категория, адрес, координаты, медиа при наличии);
   - сохранить связку с исходным предложением (`sourceSuggestionId` или аналог).

3. После успешного сохранения POI:
   - предложение помечается как обработанное/импортированное;
   - повторное создание POI из того же предложения блокируется или требует явного подтверждения.

### 2.4. UI/UX требования

- На карте должен быть видимый маркер выбранной точки.
- Для предложений точек — явная CTA-кнопка «Перейти к добавлению».
- В форме создания POI отобразить бейдж/подсказку: «Создано из предложения #ID».

### 2.5. Критерии приёмки

- Сотрудник может выбрать координаты кликом по карте без ручного ввода.
- Координаты после выбора корректно попадают в сохраняемую POI.
- Из одобренного предложения можно перейти в форму добавления с заполненными полями.
- POI успешно сохраняется, связь с предложением фиксируется, дубликат не создаётся случайно.

## 4) Интеграция с API 2ГИС

### 4.1. Область применения

Интеграция API 2ГИС используется для задач модуля сотрудников (`astrakhan-admin`):
- отображение карты в форме создания/редактирования POI;
- выбор координат кликом по карте;
- (опционально) обратное геокодирование для автоподстановки адреса по выбранной точке.

### 4.2. Технические требования

1. Ключ API 2ГИС хранится в конфигурации окружения, не в коде.
2. При отсутствии/ошибке ключа интерфейс показывает понятное сообщение и fallback:
   - ручной ввод координат остаётся доступным.
3. Координаты, выбранные на карте 2ГИС, должны сохраняться в формате:
   - `latitude` (WGS84),
   - `longitude` (WGS84).
4. Нельзя логировать приватные ключи и чувствительные параметры запроса.

### 4.3. API-сценарии

- `Map Render`: отрисовать карту с центром на городе/регионе по умолчанию.
- `Pick Point`: по клику на карту установить маркер и вернуть координаты в форму.
- `Reverse Geocoding` (если включено): по координатам получить адрес и предложить заполнение поля адреса.

### 4.4. UX-требования для 2ГИС

- Маркер должен быть один (последний выбранный клик).
- При редактировании существующей POI карта открывается с уже установленным маркером.
- Кнопка «Очистить координаты» очищает и поля, и маркер на карте.
- Ошибки 2ГИС (таймаут/лимит/недоступность) показываются в UI без блокировки формы.

### 4.5. Критерии приёмки по 2ГИС

- Сотрудник может выбрать координаты через карту 2ГИС без ручного ввода.
- При сохранении POI в БД уходят координаты из выбранной точки.
- При повторном открытии карточки POI маркер отображается в сохранённой позиции.
- При недоступности API 2ГИС форма остаётся рабочей через ручной ввод координат.

## 5) Минимальный план тестирования

### `module2`
- Курьер: адрес обязателен, заказ отправляется.
- Самовывоз: адрес клиента скрыт, требуется пункт выдачи.
- Переключение «Курьер ↔ Самовывоз» не оставляет некорректную валидацию.

### `astrakhan-admin`
- Выбор координат на карте ставит маркер и обновляет поля.
- Очистка координат удаляет маркер и очищает значения.
- «Создать POI из предложения» открывает форму с предзаполненными данными.
- После сохранения POI предложение помечается как обработанное.
- Проверка fallback: при ошибке 2ГИС ручной ввод координат остаётся доступным.
