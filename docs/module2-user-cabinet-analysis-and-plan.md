# Анализ и план развития ЛК пользователей

Документ подготовлен по текущему состоянию `module2`, `module3`, `astrakhan-admin` и требованиям по развитию личного кабинета пользователей.

## 1) Текущее состояние по приложениям

## `module2` (пользовательский фронт)

Что уже реализовано:

- Есть страница ЛК-гостя `"/orders"` с входом по email + одноразовому коду и просмотром истории заказов.
- Есть отображение базового прогресса в ЛК: количество пройденных маршрутов и посещенных точек.
- Есть уровни Bronze/Silver/Gold по числу маршрутов (локально, через `localStorage`).
- Есть избранное маршрутов и POI (локально, через `localStorage`), включая фильтр "только избранные".
- Есть шеринги маршрутов (Web Share + fallback + QR).
- Есть модалка "Новая точка на карте" и polling каталога POI.
- В AI-описаниях POI уже есть выбор аудитории: default / children / academic.

Вывод:

- База для ЛК пользователей уже создана и рабочая.
- Не хватает именно "продуктовой геймификации" с экономической ценностью (награды, бесплатный платный маршрут по условиям).
- Нет единого центра достижений, правил начисления и прозрачного прогресс-бара награды.

## `astrakhan-admin` (панель сотрудников)

Что уже реализовано:

- Формы создания/редактирования POI, маршрутов, товаров, пользователей и обработки заказов.
- В POI-форме уже есть AI-генерация описания и анализ изображения.
- На дашборде уже есть блоки "Прогресс команды" и "Достижения".

Проблемы UX форм:

- Формы перегружены длинной вертикальной структурой, без явного сценарного шага "минимум для публикации".
- Слабая валидация на клиенте для бизнес-правил (например, платный маршрут без цены, опубликованный товар без остатка).
- Недостаточно быстрых пресетов и авто-подсказок по полям (категории, теги, контактные поля, формат координат).
- Не унифицированы sticky-actions и подтверждения изменений для разных сущностей.

## `module3` (тех-админка / аналитика)

Что уже реализовано:

- Базовые API метрик: сводка, daily, heatmap.
- Дашборд с графиками, периодами и ролевой логикой.
- Есть отдельный экран `metrics.html`.

Выявленные разрывы:

- `metrics.html` обращается к `/api/metrics/activity`, но в `app.py` такого эндпоинта нет.
- В `metrics.html` идет запрос на `/api/roles`, который защищен по роли администратора; для не-админа может ломать загрузку фильтра.
- Фильтры по роли/пользователю/странице в `metrics.html` пока не поддержаны серверным API.

Вывод:

- Для тех-админки нужна консолидация API контрактов и добавление прикладных эксплуатационных метрик (не только визиты, но и ошибки, SLA, задержки, health интеграций).

## 2) ЛК пользователей в `module2`: целевая доработка

## 2.1. Перенос и развитие геймификации в ЛК пользователей

Цель: перенести идею геймификации из `docs/gamification-and-cabinet-spec.md` в пользовательский ЛК и сделать ее понятной, полезной и измеримой.

Предлагаемая структура ЛК:

1. "Мои заказы"
2. "Мой прогресс"
3. "Достижения"
4. "Награды"
5. "История активности" (посещенные точки, запущенные маршруты, избранное)

## 2.2. История заказов и статусы

Оставить текущую механику входа по email + коду, расширить блок:

- В карточке заказа добавить таймлайн статуса:
  `Подтвержден -> В обработке -> Отправлен -> Доставлен / Отменен`.
- Добавить визуальную группировку:
  "Активные", "Завершенные", "Отмененные".
- Добавить фильтры по периоду и типу маршрута (бесплатный/платный), если данные доступны.

## 2.3. Достижения (ачивки)

Минимальный набор ачивок для старта:

- "Первые шаги": посетить 3 точки.
- "Исследователь": посетить 10 точек.
- "Маршрутизатор": пройти 3 бесплатных маршрута.
- "Коллекционер": добавить 5 точек в избранное.
- "Путешественник+": пройти 2 платных маршрута.

Модель данных (локально, этап 1):

- `astra_user_achievements_v1`:
  - `unlocked: string[]`
  - `progress: Record<string, number>`
  - `updatedAt`

Переход на сервер (этап 2):

- Синхронизация достижений с аккаунтом при появлении полноценной авторизации.

## 2.4. Прогресс-бар "бесплатный платный маршрут"

Бизнес-правило из запроса:

- При выполнении условия "2 платных + 3 бесплатных маршрута" пользователь получает 1 бесплатный платный маршрут на выбор.

Рекомендуемая реализация:

- Добавить отдельный прогресс-виджет "Награда за активность":
  - `paidCompleted: 0/2`
  - `freeCompleted: 0/3`
  - итоговый progress 0..100
- После достижения условий:
  - создать reward-токен в локальном состоянии (этап 1),
  - показать CTA "Выбрать платный маршрут бесплатно",
  - пометить использованный reward.

Важно:

- Для честности начислений лучше считать "пройденный маршрут" из подтвержденного события (завершен), а не только по нажатию "Начать".
- На этапе 1 можно оставить локально, но заложить интерфейс для перехода на серверный учет.

## 2.5. Статистика в ЛК пользователя

Добавить блок "Моя статистика":

- Кол-во посещенных точек.
- Кол-во пройденных маршрутов (бесплатных/платных отдельно).
- Последняя активность.
- Кол-во избранных маршрутов и точек.
- Доступные награды и история получения наград.

## 3) Оптимизация форм сотрудников в `astrakhan-admin`

Цель: упростить работу контент-менеджеров и операторов заказов, приблизив UX к "кабинетному" сценарию с понятными шагами.

## 3.1. Общие улучшения для форм (`poi`, `routes`, `products`, `orders`)

- Разбить длинные формы на логические секции/аккордеоны:
  "Основное", "Контент", "Публикация", "SEO/теги", "Системное".
- Добавить sticky summary справа:
  - статус заполнения обязательных полей,
  - предупреждения по бизнес-валидации,
  - быстрый переход к ошибочному полю.
- Ввести унифицированный блок действий:
  - "Сохранить как черновик",
  - "Сохранить и опубликовать" (где применимо),
  - "Отмена".
- Добавить встроенную предпросмотр-карточку "как увидит пользователь в ЛК".

## 3.2. Точечные улучшения

`poi/form.html`:

- Добавить автопроверку координат (диапазон, формат, проверка swaps lat/lng).
- Добавить подсказки по качеству описания (длина, повторяемость, пустые шаблоны).
- Добавить "быстро заполнить из AI + подтвердить дифф".

`routes/form.html`:

- Жесткая валидация: если `paid=true`, цена обязательна и >0.
- Добавить drag-and-drop сортировку точек маршрута.
- Показать предпросмотр таймлайна маршрута.

`products/form.html`:

- Если `published=true`, проверять цену/остаток/изображение.
- Массовые действия по атрибутам (размеры, цвета) через шаблоны.

`orders/view.html`:

- Добавить timeline смены статусов и журнал действий оператора.
- Быстрые action-кнопки: "Подтвердить", "Отправлен", "Доставлен".

## 4) Статистика для `module3` (тех-админ)

## 4.1. Приведение API к реальному UI

Первый обязательный этап:

- Либо добавить эндпоинт `/api/metrics/activity`, либо переключить `metrics.html` на существующий `/api/metrics/daily`.
- Согласовать формат ответов:
  - единая структура `labels[]`, `series[]`.
- Обработать ролевой доступ в `metrics.html` для загрузки ролей без падения UI.

## 4.2. Метрики уровня эксплуатации (рекомендуется)

Добавить отдельные API/виджеты:

- Error rate:
  - 4xx/5xx по минутам/часам.
- Latency:
  - p50/p95/p99 времени ответа.
- Integrations health:
  - Java API, Node API, SMTP, AI provider.
- Business funnel:
  - визит -> просмотр POI -> запуск маршрута -> заказ -> оплата.
- Контентная эффективность:
  - новые POI, маршруты, просмотры, конверсия в заказ.

## 4.3. Алерты и контроль качества данных

- Алерты при резком росте 5xx, недоступности API, пустых данных метрик.
- Контроль целостности:
  - доля заказов без email/телефона,
  - "зависшие" статусы заказов,
  - POI без координат/изображений.
