## Цель

Сделать продукт более цельным за счёт:

- минимального **«кабинета гостя»** на фронте (`module2/`), без сложной авторизации;
- базовой **геймификации сотрудников** в панели (`astrakhan-admin/`), без изменения бизнес‑логики заказов/контента;
- мягкой связки активности гостя и показателей для сотрудника.

Этот файл — ТЗ для агентов Cursor.

---

## A. Фронт (`module2/`): кабинет гостя и прогресс

### A1. Страница «Мои заказы»

**Цель:** дать гостю возможность посмотреть свои заказы по `orderId` и контакту (email/телефон), используя уже существующий Java API.

#### A1.1. Маршрут и view

- Добавить новый маршрут в `module2/src/router/index.js`:
  - путь: `/orders`
  - компонент: `OrdersView.vue`

- Создать файл `module2/src/views/OrdersView.vue`:
  - макет в стиле проекта (`astra.css`):
    - заголовок «Мои заказы»,
    - краткое описание (как найти номер заказа).
  - форма поиска:
    - поля:
      - `orderId` (обязательно),
      - `contact` (email **или** телефон, опционально, но если заполнен — проверять).
    - кнопка «Найти заказ».
  - логика:
    - использовать существующий Java API:
      - `javaApi.orders.getById(orderId)` (уже есть в `backend.js`).
    - если заказ найден:
      - если поле `contact` заполнено:
        - сравнить с `order.email` **или** `order.phone` (по простому равенству, без сложной нормализации),
        - если не совпало — показывать сообщение «Заказ не найден по указанному контакту».
      - если всё ок — отобразить карточку заказа:
        - номер, дата, статус, сумма, список товаров (название, qty, цена).
    - если не найден — показать понятное сообщение.
  - состояния:
    - загрузка (спиннер/текст),
    - ошибка сети/500 (сообщение + кнопка «Попробовать снова»).

#### A1.2. API

- Не добавлять новых эндпоинтов на Java на первом этапе — использовать только `GET /api/v1/orders/{orderId}`.

### A2. Избранные маршруты и точки (favorites)

**Цель:** дать гостю возможность собирать любимые маршруты и точки; хранение — только в `localStorage`.

#### A2.1. Composable `useFavorites`

- Создать `module2/src/composables/useFavorites.js`:
  - структура хранилища:
    - `favoriteRoutes` — `Set<number>` (id маршрутов),
    - `favoritePois` — `Set<number>` (id POI).
  - хранение:
    - ключ в `localStorage`: `astra_favorites_v1`,
    - формат: `{ routes: number[], pois: number[] }`.
  - публичный API:
    - `isRouteFavorite(id: number): boolean`,
    - `toggleRoute(id: number): void`,
    - `isPoiFavorite(id: number): boolean`,
    - `togglePoi(id: number): void`,
    - `favoriteRoutesList: Ref<number[]>`,
    - `favoritePoisList: Ref<number[]>`.

#### A2.2. Интеграция в UI

- `module2/src/views/RoutesView.vue`:
  - на карточке маршрута:
    - добавить иконку/кнопку «избранное» (сердечко/звёздочка) в правый верхний угол;
    - состояние иконки зависит от `isRouteFavorite(route.id)`;
    - клик вызывает `toggleRoute(route.id)`.
  - фильтр:
    - добавить переключатель/кнопку «Только избранные» в панель фильтров,
    - при активном фильтре отображать только маршруты, id которых в `favoriteRoutes`.

- `module2/src/views/MapView.vue`:
  - в карточке/попапе POI (там, где название и описание):
    - добавить иконку/кнопку «избранное» по тому же паттерну,
    - использовать `isPoiFavorite` / `togglePoi`.

### A3. Прогресс гостя (посещённые точки / пройденные маршруты)

**Цель:** показать гостю его прогресс (локально), без обязательной привязки к пользователю на бэкенде.

#### A3.1. Composable `useGuestProgress`

- Создать `module2/src/composables/useGuestProgress.js`:
  - хранение в `localStorage` под ключом `astra_guest_progress_v1`,
  - структура:
    - `visitedPois: Set<number>`,
    - `completedRoutes: Set<number>`.
  - публичный API:
    - `markPoiVisited(id: number)`,
    - `markRouteCompleted(id: number)`,
    - `visitedPoisCount: Ref<number>`,
    - `completedRoutesCount: Ref<number>`.

#### A3.2. Точки интеграции

- `MapView.vue`:
  - при открытии детальной карточки POI (когда гость кликает по точке и открывается панель) — вызывать `markPoiVisited(poi.id)`.

- `RoutesView.vue` (или отдельная детальная страница маршрута, если есть):
  - при нажатии «Начать маршрут» — вызывать `markRouteCompleted(route.id)` **после** успешного старта (сейчас достаточно вызывать сразу).

#### A3.3. Отображение прогресса

- Либо в `OrdersView.vue`, либо в новом `ProfileView.vue`:
  - блок «Мой прогресс»:
    - текстовые счётчики:
      - «Пройдено маршрутов: N»,
      - «Посещено точек: M».
    - простой прогресс‑бар/бейджи:
      - Bronze: `N ≥ 1`,
      - Silver: `N ≥ 5`,
      - Gold: `N ≥ 10` (и/или по POI).

### A4. Поделиться маршрутом / QR

**Цель:** упростить гостю распространение маршрутов (соцсети, печать, стенды), заложить основу для аналитики.

#### A4.1. Share URL

- Для каждой карточки маршрута в `RoutesView.vue`:
  - добавить кнопку «Поделиться» в список действий (рядом с «Подробнее»/«Открыть»).
  - URL для шеринга:
    - базовый маршрут фронта (например, `/routes/:id`),
    - добавить UTM‑метки:
      - `?utm_source=share&utm_medium=route&utm_campaign=route_<id>`.
  - по клику:
    - если доступен `navigator.share` — использовать Web Share API,
    - иначе:
      - показать модалку с:
        - инпутом с URL (с кнопкой «Скопировать»),
        - кнопками «Скопировать ссылку» и «Показать QR».

#### A4.2. QR‑код

- Добавить (можно как зависимость, можно как утилиту) простую библиотеку генерации QR (например, `qrcode` или аналог):
  - новое место: `module2/src/components/common/QrModal.vue` (по усмотрению агента).
  - модалка:
    - принимает `text` (URL),
    - рендерит QR в `<canvas>` или `<img>` (data URL),
    - имеет подпись «Отсканируйте, чтобы открыть маршрут».

## B. Панель сотрудника (`astrakhan-admin/`): геймификация сотрудников

### B1. Базовый прогресс и достижения (без новых таблиц)

**Цель:** показать сотрудникам их вклад, не меняя схему БД.

#### B1.1. Сервис агрегатов

- Создать `EmployeeStatsService` в `astrakhan-admin/src/main/java/ru/astrakhan/admin/service/EmployeeStatsService.java`:
  - пока считать **общие** метрики по всей системе (не по конкретному пользователю):
    - количество:
      - точек интереса (`poiService.findAll() / findPublished()`),
      - маршрутов (`routeService.findAll() / findPublished()`),
      - товаров (`productService.findAll()`),
      - заказов (`orderService.findAll()`),
      - обращений (`feedbackService.findAll()`),
      - предложений POI (`poiSuggestionService.findAll()`).
  - подготовить структуру для фронта:
    - DTO `EmployeeStatsDto` с полями типа `Map<String, Long>` или отдельными полями.
  - подготовить список простых «ачивок»:
    - на примере:
      - `content_rich`: общее число опубликованных POI ≥ 50,
      - `routes_portfolio`: опубликовано маршрутов ≥ 10,
      - `shop_ready`: товаров ≥ 20,
      - `community_active`: обращений + предложений ≥ 30.
    - вернуть на дашборд список:
      - `id`, `title`, `description`, `status` (`LOCKED`, `IN_PROGRESS`, `UNLOCKED`), `progress` (0–100).

#### B1.2. Контроллер дашборда

- Найти контроллер, который рендерит `dashboard.html` (скорее всего `DashboardController` или основной контроллер).
- Расширить метод, который возвращает модель для дашборда:
  - добавить атрибуты:
    - `employeeStats` — значения из `EmployeeStatsService`,
    - `employeeAchievements` — список ачивок.

#### B1.3. Изменения в `dashboard.html`

- Файл: `astrakhan-admin/src/main/resources/templates/dashboard.html`.

- Под существующим блоком `.stats-grid` добавить новый раздел:

  1. **Карточка «Мой/наш прогресс»**:
     - заголовок: «Прогресс команды» (позже можно персонализировать).
     - список ключевых показателей:
       - «Опубликованные точки»,
       - «Опубликованные маршруты»,
       - «Товары в магазине»,
       - «Обработанные обращения/предложения».

  2. **Карточка «Достижения»**:
     - заголовок: «Достижения».
     - сетка бейджей:
       - название ачивки,
       - короткое описание,
       - статус:
         - если `UNLOCKED` — яркий бейдж,
         - если `IN_PROGRESS` — полупрозрачный с прогресс‑баром,
         - если `LOCKED` — серый.

Верстку делать на существующих классах `card`, `stats-grid`, `tag`, `status-badge` из `astra.css`/`admin.css`.

## C. Шаги после реализации (на сервере)

1. Локально проверить:
   - `astrakhan-admin`: `mvn -q clean package -DskipTests`,
   - `module2`: `npm install` (или `npm ci`) и `npm run build`.

2. Запушить изменения в `main`.

3. На сервере:

```bash
cd /opt/astramicro
bash deploy/update.sh
```

4. Проверить:
   - `http://<host>/java-api/admin` → дашборд с новым блоком прогресса/ачивок,
   - `http://<host>/` → фронт:
     - маршрут `/orders`,
     - избранные маршруты/POI,
     - счётчики прогресса.
